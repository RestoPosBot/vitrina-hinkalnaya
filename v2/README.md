# Витрина Хинкальной

Витрина для гостя: выбрать заведение или адрес, посмотреть меню, собрать корзину,
оформить самовывоз или доставку. Сначала телефон. Витрину можно поставить на домашний
экран, и меню открывается без сети.

Меню настоящее. Это снимок боевой базы Хинкальной: 7 заведений, 13 разделов, 133 блюда,
цены и стоп-листы по каждому заведению. Заказ никуда не уходит, это демонстрация.
Номер заказа и «прошлый заказ» хранятся только на телефоне гостя (localStorage).

## Как запустить у себя

Нужен любой статический сервер: модули ES не открываются с `file://`.

```
py -m http.server 8778 --bind 127.0.0.1 --directory C:\resto-testing
```

Потом откройте в браузере http://127.0.0.1:8778/vitrina_hinkalnaya/.
Лучше в режиме телефона: в инструментах разработчика нажмите Ctrl+Shift+M.

Сборки нет, npm-пакетов тоже. Файлы отдаются как есть.

## Как устроено

Маршруты живут в адресе после `#`:

| Адрес | Экран |
|---|---|
| `#/adres` | где вы: «я рядом», список заведений, адрес доставки |
| `#/` | главная: шапка с заведением, поиск, сторис, разделы, карточки |
| `#/blyudo/<id>` | карточка блюда (шторка поверх главной) |
| `#/korzina` | корзина (шторка) |
| `#/perenos` | «Переносим заказ»: заведение сменилось, а корзина уже собрана |
| `#/oformlenie` | оформление: способ, время, имя, телефон |
| `#/gotovo/<номер>` | заказ принят |
| `#/poisk` | поиск с исправлением раскладки |

Кнопка «назад» на телефоне закрывает шторку или сторис и не выкидывает из витрины.

## Проверка

Проверочные скрипты лежат не в этом репозитории, а в рабочем проекте рядом с ним
(`C:\resto-testing\scripts\`, папка витрины — `C:\resto-testing\vitrina_hinkalnaya\`).
Команды ниже запускаются из `C:\resto-testing`:

- `py -X utf8 scripts/proyti_vitrinu.py` — гость проходит всю витрину кликами:
  адрес → меню → сторис → блюдо → корзина → смена заведения → перенос → оформление →
  готово → поиск. Снимки попадают в `screenshots/prohod_*.png`, журнал — в
  `logs/vitrina_prohod.txt`.
- `py -X utf8 scripts/proverit_yadro.py`, `proverit_adres_perenos.py`,
  `proverit_korzinu_oformlenie.py` — проверки отдельных частей.
- `py -X utf8 scripts/proverit_pwa_k2.py` — трафик первого и второго захода, оффлайн,
  плохая сеть (журнал `logs/pwa_k2.txt`); `scripts/proverit_pwa_fiks.py` — выпуск новой версии;
  `scripts/proverit_manifest_vitriny.py` — манифест глазами Chrome.

## Сеть, кеш и обновления

Сервис-воркер `sw.js` держит три правила.

1. **Код и оболочка — снимком.** Страница, `stil.css`, модули `js/**`, шрифты, favicon и
   превью сторис ложатся в кеш одним набором при установке воркера и дальше берутся
   из кеша без сети. Поэтому витрина открывается сразу даже на плохой связи, а ленивые
   экраны `js/ekrany/*.js` всегда той же версии, что и ядро. Тяжёлое и не нужное первому
   экрану (значки установки, картинки сторис целиком, около 1 МБ) берётся по требованию,
   а впрок — только со второго захода.
2. **Меню свежее, но без ожидания.** Копии `menyu.json` и `istorii.json` меньше 10 минут —
   гость получает её сразу, сеть обновляет кеш в фоне. Копия старше — запрос в сеть; нет
   ответа за 1,5 секунды — копия из кеша, свежий ответ дописывается для следующего захода.
   Без сети — копия из кеша.
3. **Фото блюд — свой кеш, трафик гостя бережём.** Первый заход качает только фото, которые
   гость увидел (около 1,3 МБ на весь первый заход вместе с кодом). Со второго захода воркер
   в фоне докачивает превью всех блюд `foto/m/` (около 2,5 МБ), если у гостя не включена
   экономия трафика, связь не 2G и не сотовая (Chrome на Android это сообщает). Оригиналы
   впрок не качаются: оригинал ложится в кеш, когда гость открыл блюдо. Без сети плитка
   берёт превью из кеша. Этот кеш не сбрасывается при выпуске кода, только при замене фото.

**После любой правки кода, стилей, значков или фото** пересчитайте версии, иначе гости
не получат изменения. Из папки витрины:

```
py -X utf8 instrumenty/obnovit_versiyu_sw.py
```

Скрипт кладёт в `sw.js` хеши опубликованных файлов (`VERSIYA` — код, `VERSIYA_FOTO` — фото
и превью; закрытое `.gitignore` не считается) и предупреждает, если новый модуль в `js/`
забыли вписать в список `OBOLOCHKA`. Меню (`menyu.json`) версию не трогает: оно и так
берётся из сети. В рабочем проекте его же зовёт `scripts/obnovit_versiyu_sw.py`, а
`scripts/proyti_vitrinu.py` пересчитывает версии сам перед проходом.

Чтобы не забыть, поставьте хук: он не пустит коммит со старыми версиями или с
пересчитанным, но не добавленным `sw.js`. Один раз, из папки витрины:

```
cp instrumenty/hooks/pre-commit .git/hooks/pre-commit
```

Как новая версия доходит до гостя: браузер замечает изменённый `sw.js` и ставит новую
версию в фоне. Открытые вкладки доживают на старой целиком. При следующем открытии витрины,
когда других её вкладок нет, страница один раз мигает фоном и открывается уже новой.

При разработке у себя: после правки файла без пересчёта версий браузер покажет старый код
из кеша. Либо запустите скрипт выше, либо в инструментах разработчика откройте
Application → Service workers и включите Update on reload.

Значки рисует `scripts/narisovat_ikonki_vitriny.py`, заставки iOS при запуске с домашнего
экрана (`ikonki/zastavka-*.png`) — `scripts/narisovat_zastavki_ios.py`, скриншоты для
диалога установки — `scripts/snyat_skrinshoty_manifesta.py`.

## Что публикуется

Публикуется только то, что лежит в git: витрина живёт на GitHub Pages из этого репозитория.
GitHub Pages сам сжимает js, css и json (gzip), поэтому реальный вес кода в сети примерно
втрое меньше, чем на диске. Не заливайте папку целиком копированием или архивом: рядом
лежат рабочие файлы, которые гостю не нужны.

| Что | Зачем лежит | В публикации |
|---|---|---|
| `foto_yandex/` | исходники фото (75 МБ) для `scripts/polozhit_foto_yandex.py` | нет, закрыто `.gitignore` |
| `opisaniya.json` | составы и описания для сборки меню | нет, закрыто `.gitignore` |
| `konsepty/` | исходные концепты дизайна | нет, закрыто `.gitignore` |
| `kartinki/prevyu_istochnik.html` | исходник картинки превью ссылки `kartinki/prevyu.jpg` | нет, закрыто `.gitignore` |
| `instrumenty/` | пересчёт версий воркера и хук для git | да, воркер их не трогает |
| фото в `foto/` и `foto/m/`, на которые не ссылается `menyu.json` (28 + 7 шт., 1,5 МБ на 01.10) | остались от прошлых сборок меню | да, но воркер их не качает. Убрать: `py -X utf8 scripts/najti_lishnie_foto.py --perenesti` переносит их в `foto_lishnie/` (закрыта `.gitignore`), `scripts/sobrat_menyu_iz_bazy.py` при нужде скачает заново |

`konsepty/` и `opisaniya.json` уже были в git. Чтобы они ушли из публикации, их надо один
раз убрать из индекса (файлы на диске останутся):

```
git -C vitrina_hinkalnaya rm -r --cached konsepty opisaniya.json
```
